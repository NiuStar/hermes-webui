# 存储优化与 .10 正式验收

## 用户授权与边界
- 按已讨论顺序：控制新增日志重复写入、优化数据库索引、逐步减少重复正文持久化，最后独立决定存量清理。
- 不新增测试部署环境；代码级回归仍执行，运行验收直接在 .10 正式服务进行。
- 不删除现存数据库、备份、迁移残片或历史日志；存量淘汰须独立列范围授权。
- 不按内容相同去重、不删除 inactive 历史、不损坏工具关联、截断和继续对话上下文。

## 实施门禁
1. 保护当前数据、核对无并发导入，记录正式版本、库表/索引占用和文件计数。
2. 日志仅在可证明恢复等价时压缩重复 payload；未完成持久化与 ephemeral 运行保留。
3. Sidecar 减少序列化冗余但兼容 metadata-prefix 读取；不是声称已统一正文存储。
4. 审计 Agent 重复入库路径，任何改动必须由真实调用链及回归测试支撑。
5. 保留版本化变更与不可变镜像，代码回归后在 .10 正式环境验收。
6. 真实会话列表/分页/完整正文、工具关联、中文全文搜索、续聊及终态日志恢复分别验证。
7. 比较一次等价受控运行的新增数据库、sidecar、journal 字节；压缩包大小不当运行占用收益。
8. 全部指标与未完成项分别报告；仅文件到位/API metadata 通过不能宣称迁移或优化全部完成。
