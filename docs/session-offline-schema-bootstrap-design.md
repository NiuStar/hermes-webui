# 专用展示库离线初始化方案（候选）

状态：DESIGN_REVISED / REVIEW_BLOCKED。固定旧版本ebadd350f068ec48676583549f3d0f29f980ef56已收到独立文本审查，本次在当前会话逐项修订与作者复核，未冒充新版本独立终审。以§8修订契约为准，前文保留背景，不得单独据此实现。用户本轮仅批准先设计并审查离线初始化方案；不批准实施、发布、替换、删除数据库。本文件不修改既有业务DDL或授权契约。正式GET保持LEGACY。

## 1. 问题与证据

当前initialize(connection)先检查目录，再切换WAL，最后BEGIN IMMEDIATE；真实竞争者可在检查间隙创建未知表，入口拒绝却持久改变未知库日志模式。事务回滚不能撤销模式切换。证据：`/workspace/history-failure-evidence/schema-p2-resolution/foreground-combined-unicode/`，105通过、3失败（WAL竞争1；共享信号量权限2）。不能通过重新命名失败或恢复竞争者PRAGMA关闭缺陷。

同轮binding修复仅增加严格UTF-8可编码性检查，不归一化输入；18个真实RED，修复后45个模块测试通过。证据同目录下`foreground-unicode-red/`及`foreground-unicode-green/`。该修复未独立终审，未提交产品代码。

## 2. 生命周期拆分

- 离线创建者只接受受控父目录和新的随机候选标识，不接受任意已有数据库连接；已有路径无论内容如何均拒绝，不truncate、不覆盖、不修复。
- 在线验证者只接收已发布清单指定的库。禁止设置journal_mode，未知目录/模式/版本失败关闭。连接级FK/FULL设置须与持久模式验证明确区分，不能声称任何失败都没有连接级变化。
- 旧initialize接口未完成迁移与测试前仍标阻断，不同时保留一个可绕过新生命周期的生产入口。
- 初始化成功只表示空库结构合格，不表示业务invariant、源门、终态、SEALED或ELIGIBLE合格。

## 3. 离线候选步骤

1. 预检父目录权限、文件系统能力、磁盘预算和目标不存在。无平台能力或预算证据则拒绝启动。候选必须在最终发布所在文件系统内。
2. 使用不可预测标识、排他创建私有目录和新文件；拒绝符号链接、路径穿越、硬链接别名及目录替换。实现必须使用目录句柄与无跟随语义并验证文件身份，不能仅以resolve/exists作TOCTOU保护。SQLite实际打开路径的身份绑定属于编码设计待证明项。
3. 仅创建者可访问候选。安装获批原样DDL，核验精确目录、完整性和空状态；失败保留候选与审计，禁止自动删除。合作方advisory lock不构成任意写方排除。
4. 设置并读回WAL/FULL/FK；完成事务，执行checkpoint并确认无busy及无剩余未归并页，关闭所有候选连接。不得只复制主db而遗漏有效WAL；不得手删-wal/-shm。
5. 关闭后对候选文件清单与身份取证，使用严格只读方式重新验证结构和持久模式。只读验证如何不生成或依赖未列出的sidecar须按目标SQLite/文件系统实测；不得假设immutable参数自动安全。
6. 对主文件、必要文件、清单执行适当fsync及目录同步。清单包含候选ID、DDL版本/hash、创建者版本、SQLite版本、文件身份、字节/hash、验证结果、预算与批准范围，不含秘密。

## 4. 发布边界（当前不实施）

推荐不可变候选目录加一次性发布清单；不移动正在打开的SQLite文件，不覆盖现有state.db，也不热替换活动连接。

发布端持真实访问门并证明无候选写方，核验候选与清单；最终目标存在即拒绝。必须使用经过平台验证的原子no-replace原语，不能用exists后rename或普通可覆盖rename。同步发布目录后再确认提交。发布失败/崩溃状态不确定时，重启只读核验目标与候选ID；不盲目重试覆盖。

本设计仅涵盖首次专用空展示库发布。将现有运行服务改指向该库、生成数据或替换既有库均是单独授权阶段。发布后的业务库会发生合法写入，初始文件hash仅证明发布时字节，在线验证不能拿它当永久不变条件；在线验证依赖持久身份、版本和业务约束。

## 8. 当前修订契约（覆盖前文有歧义处）

### 8.1 属性与连接责任：对应P1-1

只有journal_mode等经目标版本验证的属性属于持久数据库状态。FK=ON和synchronous=FULL属于每个连接的策略；清单记录“所需策略”和创建时读回值，不记录“永久安装成功”。受控在线连接工厂不得接受调用方任意连接；创建后、任何业务SQL前设置并读回FK/FULL，失败关闭该连接，不接入连接池。重连、池重建、并发新连接及进程重启都重复检查。在线入口不得设置journal_mode；已存在库模式不合格即拒绝，不能自动修复。

风险：漏掉一个连接入口即弱化持久性。对策：枚举连接创建者并收敛到工厂；验证：逐入口负对照及连接生命周期测试；回退：未闭包前LEGACY。

### 8.2 威胁模型与身份绑定：对应P1-2/P1-3

撤销“目录权限可以排除同UID非受控进程”的暗示。产品要求仍排除非受控写方，因此建议采用**独立专用UID的短时创建/发布进程**，其受保护父目录不可由WebUI UID或其他服务UID写入；同专用UID不承载其他任务。root/宿主管理员与内核属于可信管理边界，不宣称可防这些主体。该UID/权限路线仅为设计提案，未获部署授权，当前.10是否满足尚未实测。

选择标准SQLite VFS加受保护命名空间，不在本轮引入自定义VFS或/proc/self/fd路径技巧。目录句柄与O_NOFOLLOW用于前后检查，不能证明SQLite按路径重开的身份；实际安全前提是SQLite打开全过程中不存在可替换目录/主库/sidecar的非受控写方。必须验证父目录祖先、所有权、权限、ACL、挂载别名与容器映射；未知任一条件即拒绝。主文件要求常规文件、链接数1，记录dev/ino；打开前后与关闭后比较主文件身份。WAL/SHM按固定名称在受控目录内由同一SQLite生命周期管理，不能沿用同名外部文件。

风险：专用UID只是名字，实际仍共享权限。对策：以OS访问负对照证明，而非进程列表快照；验证：WebUI UID、其他UID、目录替换、symlink/hardlink与竞争访问均应被拒绝，同UID攻击不能声称权限测试可阻断；回退：不具备隔离前提不创建、不发布。独立UID方案是否被批准是显式未决门。

### 8.3 唯一发布单元与信任锚：对应P1-4

发布单元固定为完整候选目录，包含`display.db`和`manifest.json`；不覆盖或复用真实`state.db`。清单列主库SHA、字节、候选ID、DDL摘要、平台证据、连接策略与验证结果；UTF-8规范JSON、键排序、无多余空白、整数禁止bool，不包含自哈希。候选冻结后生成清单摘要。

在候选目录外的受保护批准记录中持久写入候选ID、清单摘要、目标名称与授权范围；批准记录由发布主体控制，不能由候选内容自行授权。摘要防止意外替换，安全信任来自批准记录的权限与审查来源，不来自普通hash本身。

发布顺序固定：关闭SQLite并满足8.4→主库fsync→清单写入并fsync→候选目录fsync→批准记录持久化及其目录fsync→重新核验候选与批准摘要→同文件系统renameat2(RENAME_NOREPLACE)整个目录→源、目标父目录分别fsync→写发布完成记录并同步→读回匹配。rename成功是可见性线性化点，不是断电持久完成点；激活不得发生在全部同步/读回前。

重启遇到目标已存在：只读验证其候选ID及外部批准记录；不同ID或摘要失败关闭，同ID也不能仅凭路径存在认定同步已完成，须完成可幂等核验与持久确认。无覆盖降级实现，EXDEV/ENOSYS/不支持目录同步均BLOCKED。

风险：目录发布和批准记录不是单事务。对策：批准先行、发布后完成记录、身份幂等；验证：每个边界中断、双发布者、已有目标保真；回退：不激活，保留候选和批准记录，不删除或覆盖。

### 8.4 WAL制品与验证范围：对应P1-5/P1-6

首次发布制品明确为主库与清单，不含WAL/SHM/journal。候选连接执行checkpoint(TRUNCATE)，确认成功且无未归并页，正常关闭所有连接；仅在SQLite自行清理sidecar且目录实际满足精确白名单时继续。残余sidecar不手删，不假定零字节即可安全忽略；失败即隔离保留。

首次离线复核限定为已受控创建、已关闭、无sidecar、主文件hash/身份匹配的候选，使用mode=ro&immutable=1只读连接，在只读事务内比较精确schema与空状态；immutable在此只基于冻结且无恢复需求的候选，不用于未知库或活动业务库。复核前后比较文件身份、内容、目录集合，任一变化拒绝。

在线验证拆成两层：未经可信批准记录绑定的任意路径**不打开SQLite**，直接拒绝，不能把hot journal库拿来探测；可信已激活业务库按正常SQLite恢复/锁/sidecar语义打开，结构验证使用一致读事务。撤销“在线打开任何库都无文件系统副作用”的笼统保证，限定为“不对未知库执行打开/修复，不在线切换日志模式”。可信业务库的合法恢复副作用不能伪称零写入。是否允许首次激活创建WAL/SHM属于后续激活设计，当前不实现。

风险：冻结条件被破坏导致immutable读错。对策：8.2真实权限门贯穿复核和发布；验证：残余WAL、hot journal、缺SHM、只读目录、打开时竞争替换分别拒绝或按可信运行契约验证；回退：原失败测试保留，新的接口测试不得删除旧反例冒充修复。

### 8.5 精确结构、资源与失败候选：对应P2-1至P2-6

- 结构仍使用获批SQL在同一SQLite版本生成参考目录，与(type,name,tbl_name,sql)逐项比较；不采纳审查中泛化的“禁止SQL字符串相等”建议，因为本项目要求固定原样DDL和版本匹配。不得放宽已有17表/66trigger/35index契约。内部对象也由参考目录确定，不忽略sqlite_前缀。
- 空状态要求每张批准业务表无行，sqlite_sequence等内部状态与同版本参考库一致；application_id/user_version记录并与参考库相等，不擅自新增版本标记或改变DDL。
- 离线验证要求integrity_check完整返回唯一ok、foreign_key_check零行、精确目录及空状态一致。页数量/大小记录用于资源和一致性检查，不宣称可以替代完整性检查。业务invariant独立未完成。
- 候选构建并发固定1。资源策略必须提供max_candidate_bytes、min_free_bytes、max_retained_candidates、max_rss_bytes、max_elapsed_seconds与检测周期；任何缺项、越界或已有失败候选数量达到上限则拒绝新建。每阶段及每次可增长写入前检查预算；磁盘硬上限需由受审配额或限额机制落实，轮询本身不能保证不超限。具体数值必须由.10实测与批准给出，不凭空写默认安全值。
- 平台仅拟支持.10实际Linux本地文件系统；内核、挂载类型/参数、容器bind映射、SQLite版本/compile_options/VFS均须记录。NFS、overlay承载候选、跨设备发布和Windows不自动支持；缺目标平台证据即BLOCKED。
- 失败候选在外部注册表标FAILED/QUARANTINED；发布只接受与批准记录匹配的VERIFIED候选。中断无状态按未知隔离处理，不凭名称重用。不设置自动删除期限；达到保留上限停止创建，列候选清单请求用户明确删除授权后才可执行清理并保留审计。
- 证据清单绑定源码commit、文档SHA、命令、环境、XML/exit/log SHA与预期失败断言；旧测试数量不计作新生命周期测试。故障注入只针对获批自有候选，不kill正式服务，不将进程退出冒充断电测试。
