# 专用展示库离线初始化方案（候选）

状态：DESIGN_DRAFT / INDEPENDENT_REVIEW_PENDING。用户本轮仅批准先设计并审查离线初始化方案；不批准实施、发布、替换、删除数据库。本文件不修改既有业务DDL或授权契约。正式GET保持LEGACY。

## 1. 问题与证据

当前initialize(connection)先检查目录，再切换WAL，最后BEGIN IMMEDIATE；真实竞争者可在检查间隙创建未知表，入口拒绝却持久改变未知库日志模式。事务回滚不能撤销模式切换。证据：`/workspace/history-failure-evidence/schema-p2-resolution/foreground-combined-unicode/`，105通过、3失败（WAL竞争1；共享信号量权限2）。不能通过重新命名失败或恢复竞争者PRAGMA关闭缺陷。

同轮binding修复仅增加严格UTF-8可编码性检查，不归一化输入；18个真实RED，修复后45个模块测试通过。证据同目录下`foreground-unicode-red/`及`foreground-unicode-green/`。该修复未独立终审，未提交产品代码。

## 2. 生命周期拆分

- 离线创建者只接受受控父目录和新的随机候选标识，不接受任意已有数据库连接；已有路径无论内容如何均拒绝，不truncate、不覆盖、不修复。
- 在线验证者只接收已发布清单指定的库。禁止设置journal_mode，未知目录/模式/版本失败关闭。连接级FK/FULL设置须与持久模式验证明确区分，不能声称任何失败都没有连接级变化。
- 旧initialize接口未完成迁移与测试前仍标阻断，不同时保留一个可绕过新生命周期的生产入口。
- 初始化成功只表示空库结构合格，不表示业务invariant、源门、终态、SEALED或ELIGIBLE合格。

## 3. 离线候选步骤

1. 预检父目录权限、文件系统能力、磁盘预算和目标不存在。无平台能力或预算证据则拒绝启动。候选必须在最终发布所在文件系统内。
2. 使用不可预测标识、排他创建私有目录和新文件；拒绝符号链接、路径穿越、硬链接别名及目录替换。实现必须使用目录句柄与无跟随语义并验证文件身份，不能仅以resolve/exists作TOCTOU保护。SQLite实际打开路径的身份绑定属于编码设计待证明项。
3. 仅创建者可访问候选。安装获批原样DDL，核验精确目录、完整性和空状态；失败保留候选与审计，禁止自动删除。合作方advisory lock不构成任意写方排除。
4. 设置并读回WAL/FULL/FK；完成事务，执行checkpoint并确认无busy及无剩余未归并页，关闭所有候选连接。不得只复制主db而遗漏有效WAL；不得手删-wal/-shm。
5. 关闭后对候选文件清单与身份取证，使用严格只读方式重新验证结构和持久模式。只读验证如何不生成或依赖未列出的sidecar须按目标SQLite/文件系统实测；不得假设immutable参数自动安全。
6. 对主文件、必要文件、清单执行适当fsync及目录同步。清单包含候选ID、DDL版本/hash、创建者版本、SQLite版本、文件身份、字节/hash、验证结果、预算与批准范围，不含秘密。

## 4. 发布边界（当前不实施）

推荐不可变候选目录加一次性发布清单；不移动正在打开的SQLite文件，不覆盖现有state.db，也不热替换活动连接。

发布端持真实访问门并证明无候选写方，核验候选与清单；最终目标存在即拒绝。必须使用经过平台验证的原子no-replace原语，不能用exists后rename或普通可覆盖rename。同步发布目录后再确认提交。发布失败/崩溃状态不确定时，重启只读核验目标与候选ID；不盲目重试覆盖。

本设计仅涵盖首次专用空展示库发布。将现有运行服务改指向该库、生成数据或替换既有库均是单独授权阶段。发布后的业务库会发生合法写入，初始文件hash仅证明发布时字节，在线验证不能拿它当永久不变条件；在线验证依赖持久身份、版本和业务约束。

## 5. 崩溃与回退

| 崩溃点 | 恢复规则 | 回退 |
|---|---|---|
| 候选创建前/中 | 未发布不可见；记录不完整候选，拒绝沿用未经验证的内容 | LEGACY，保留文件 |
| DDL/WAL/checkpoint中 | 候选可能保留WAL及部分初始化状态；不把失败候选当空库重新覆盖 | 保留审计，人工决定新建候选 |
| 关闭后验证/同步前 | 没有发布凭据，重新只读核验或阻断 | 不开放在线写 |
| 原子发布前 | 仅候选存在，不可见于在线入口 | LEGACY |
| 发布后目录同步前 | 结果不确定；读回身份与清单，不能声称断电持久 | 阻断激活，保留双方 |
| 发布同步后激活前 | 幂等识别同一候选，不创建第二份“成功” | 保持未激活 |
| 激活后 | 不属于本轮；须另审连接生命周期和源/业务资格 | 禁止自动回切或删库 |

## 6. 风险、对策、验证与门禁

| 风险 | 对策 | 必须验证 | 失败/回退 |
|---|---|---|---|
| 未知已有库被改动 | 在线不切模式；创建者只建新目标 | 原WAL竞争反例改为在线拒绝无持久变化；比较内容/模式 | 保留原库，LEGACY |
| 路径被替换/别名访问 | 目录权限、身份绑定、无跟随、真实访问门 | symlink/hardlink/目录替换/第二进程反例 | 无身份闭包即BLOCKED |
| 多候选发布覆盖 | 原子no-replace+固定候选ID | 双进程同时发布只一个成功、已有目标字节不变 | 保留失败候选 |
| 丢失有效WAL | 完整checkpoint/close/清单验证，不单独拷贝主文件 | 故意保留WAL、busy读者、关闭失败 | 禁止发布 |
| 文件持久但目录不持久 | 文件及目录同步，平台能力门 | 可控测试目录逐阶段崩溃；进程kill不冒充断电 | 不确定即不激活 |
| 哈希被误当在线不变性 | 区分发布证据和运行时约束 | 合法写后在线结构验证仍正确，篡改版本拒绝 | 不授予业务资格 |
| 候选占满磁盘 | 预先量化预算/上限，串行构建，超限停止新增写入 | 故障注入限额、RSS/I/O/峰值测量 | 不杀生产、不自动删候选 |
| 平台原语差异 | 对.10实际文件系统验证，不外推Windows/NFS | 原子性、fsync、权限/锁能力清单 | 未支持平台失败关闭 |
| “离线”但有其他写方 | 排除同用户非受控进程、共享目录和路径替换者；无法证明则阻断 | 写方枚举与权限负对照 | 不以advisory lock放行 |

## 7. 前台自审与未决项

本轮作者自审已指出并写入：普通rename会覆盖；主db hash不适用于运行后；WAL关闭/checkpoint不等于可安全搬移；进程崩溃不等于断电；创建文件后SQLite重开仍有路径身份窗口。这是作者自审，不是独立终审。

进入编码设计前必须独立解决：SQLite连接与文件身份绑定的可执行实现；目标平台no-replace与目录同步支持；只读复核sidecar边界；真实访问门证明方式；资源预算；首次发布清单与后续在线连接的绑定。任何一项未决都不允许以文档承诺视作已实现。

用户要求禁止后台任务，因此本轮未调用后台子代理。独立审查尚未执行；需要经用户认可的同步独立审查通道或外部审查者。设计接受后仍须完成编码设计及独立终审，再请求实施授权。所有新生命周期测试目前NOT_RUN。
