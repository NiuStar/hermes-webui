## V2-01 / P1：隔离终态与历史完成记录的恢复优先级冲突

位置：75—86行。
75行允许任意状态转QUARANTINED，77行声明其为终态；86行却规定S无/T有/A匹配/C有即返回PUBLISHED_UNACTIVATED，没有要求最新注册状态仍为已发布，也没有说明C仅指最新记录。

反例：合法完成记录seq=n；后续发现冲突追加QUARANTINED seq=n+1；冲突对象随后不再出现，目标和批准又匹配。恢复按历史C存在的分支可重新报成功，与终态禁止重用矛盾。即使实现者选择安全解释，当前也存在两种相反实现，不能放行。

关闭条件：先核验完整注册链并以最新有效记录判定终态；FAILED/QUARANTINED在任何文件组合下都不得恢复成功；明确定义C是历史证据还是最新状态，并规定历史完成记录不能覆盖后续隔离。添加“完成→隔离→文件恢复匹配”的反例，要求保持隔离、无rename、无成功记录。

风险/回退：被撤销候选重新获成功资格；最新终态优先，歧义未消除保持BLOCKED。

## V2-02 / P2：结果类型无法表达文档规定的成功和早期失败

位置：30、40—48行。
PublishResult.code必填enum，但46行只列错误码，没有成功码或成功时允许null；输入校验/获取锁失败可能尚无候选ID，却要求返回必填candidate_id/target_name；CandidateResult成功描述要返回manifest摘要，但结果类型只有未定义语义的evidence_sha。acquire_bootstrap_context仅声明返回BootstrapContext，没有前置拒绝的异常类型契约。

关闭条件：明确使用带判别字段的成功/拒绝联合类型或正式异常协议；成功码、无候选失败字段、manifest_sha与evidence_sha分别定义；每个API逐项明确抛异常还是返回拒绝及其优先级。测试在尚未创建ID、LOCK_BUSY、成功VERIFIED和发布成功时都能按唯一schema序列化。

风险/回退：调用者猜测空ID/错误码，错误被误报成功；定义前不实现公共接口。

## V2-03 / P2：目标名称约束与竞争测试互相矛盾

位置：68、91、129行。
68行固定target_name=candidate_id，候选ID又唯一；129行要求两个不同候选竞争同一目标。正常API不能同时满足这两个条件。若为了测试允许不同候选指定同一target，反而违反批准绑定。

关闭条件：保留目标名=候选ID时，端到端测试改为同候选/同批准重复发布进程，分别验证LOCK_BUSY及重试幂等；不同候选同目标只在低层no-replace原语测试，不冒充合法业务场景。明确全局锁下如何实际触发底层EEXIST（预存目标或受控故障注入），不靠绕过真实权限门。

风险/回退：为实现不可达测试放宽生产接口；分层测试，目标绑定不变。

## V2-04 / P2：策略及审批摘要的精确绑定仍未闭合

位置：25—29、40、52、58、71行。
文档同时出现approved_policy_sha、resource_policy_sha、ApprovalRecord.policy_sha和ctx策略摘要；固定部署策略仅有字段名散述，没有完整类型、规范字节或说明policy_sha覆盖哪一种策略。candidate_id与target_name的等值关系、审批里的manifest摘要应与哪次实时重算值比较，也未形成唯一匹配列表。“批准精确匹配”仍需实现者补充规则。

关闭条件：定义DeploymentPolicy精确schema和受保护读取路径；明确各摘要覆盖对象、规范字节与依赖关系；列出审批匹配等式和创建到发布期间策略变化的唯一处理（拒绝旧批准，或规定重新批准流程），不得混用平台证据与权限能力。用逐字段/逐摘要变化反例验证零rename。

风险/回退：配置变更后错误沿用旧批准；不匹配失败关闭，不自动重签或重写审批。
