## 1. 目标与依据

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D22（含验证及回退）。

将“打开会话时全量重算”改为“写入侧增量维护、后台整理、读取侧直接分页”。稳定历史与正在生成的轮次分离，保留原始数据和现有恢复语义。

依据 `docs` 中的细分计时诊断及 `/workspace/hermes-latency-diagnosis/fine-report.md`：两个长会话重复执行约1.45–1.66秒历史合并，再花约473–484毫秒扫描缓存大小；合并缓存超过32 MiB门槛被拒绝。模型上下文容量函数另有秒级等待。不以增大缓存上限代替读路径改造。

## 2. 核心原则

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D07、D10、D25（含验证及回退）。

1. 已完成历史形成可直接分页读取的展示结果，不随页面刷新重新合并数据库、sidecar和父链。
2. 正在生成的数据同样必须持久化，内存缓存不是权威数据源。
3. 整理边界为一次运行/轮次结束，不等待整条会话永久结束。
4. 复用现有journal追加写与增量事件能力，不将既有机制宣称为新增。
5. SQLite及现有原始存储的权威边界保持不变；历史展示结果是可重建的派生视图，不取代推理上下文。
6. 不将展示整理等同于模型上下文压缩，不按正文相同直接去重。

## 3. 数据流

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D07、D08、D11、D13（含验证及回退）。

```text
模型输出 / 工具事件
        |
        v
活动事件日志：有序追加、持久化、可重放
        |
        +--> 内存热缓冲 --> SSE实时展示
        |
        +--> 轮次终态 --> 持久化整理任务
                              |
                              v
                       后台增量整理与校验
                              |
                              v
                       原子发布历史展示版本

页面读取 = 稳定历史指定页 + 尚未归档的活动增量
```

历史数据存储不是队列；队列用于传递整理任务。活动事件日志、整理任务队列和稳定历史展示存储职责分开。

## 4. 写入侧预维护的数据

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D12、D17、D18、D19（含验证及回退）。

| 数据 | 维护时机 |
|---|---|
| 展示合并、顺序与分页索引 | 轮次结束后台增量整理；破坏追加语义的操作重建受影响版本 |
| 消息总数、最后消息时间 | 事件写入或展示版本更新时维护，区分原始事件数与展示消息数 |
| 工具调用与消息关联 | 工具事件持久化时维护，归档时校验 |
| 最新Todo状态 | Todo更新时保存，显式空列表同样是有效最新状态 |
| 上下文容量、阈值展示信息 | 模型或配置变化时刷新，绑定配置身份与版本 |
| 展示结果大小与预算信息 | 展示版本生成时计算，不随GET重复全量扫描 |

GET保留权限、必要脱敏、来源版本有效性检查及活动状态读取，不能为性能删除这些边界。上下文容量缺失或过期明确标记，后台限时刷新，不阻塞正文；实际推理和压缩仍进行权威容量校验。

## 5. 版本、水位与一致性

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D01、D08、D09、D11、D14、D24（含验证及回退）。

### 概念字段（编码设计阶段确定实际schema）

- 会话身份：profile/source/session_id，保持权限与来源隔离。
- 活动身份：run_id及单调事件序号；跨run不能仅用局部序号比较。
- 展示版本：generation、源修订签名、构建状态、展示消息数与分页边界。
- 归档水位：版本已覆盖的事件范围或每run水位。
- 整理任务：幂等键、输入修订、重试次数、状态和错误信息。

### 读写协议

1. 事件先持久化，再确认可靠接收；具体fsync/批次确认策略在编码设计中明确，不能把内存入队称为可靠落盘。
2. 运行正常完成、失败、取消或中断后，均将已有有效事件纳入可恢复整理流程。
3. 终态持久化与整理任务登记应原子完成，或以持久化outbox/启动扫描补偿，防止终态存在但任务丢失。
4. worker按固定输入修订及水位构建候选版本，幂等执行、允许重试。
5. 校验消息顺序、关联、数量、截断/分支规则及来源签名后，原子切换当前版本指针。
6. 发布使用修订比较，过期worker不得覆盖编辑、再生成或新轮次形成的新版本。
7. 一次读请求固定历史版本及其水位，再读取水位之后的活动事件；归档切换期间也不能重复或遗漏。
8. SSE与GET必须有可对齐的事件游标；浏览器重连不应重复展示已纳入历史的增量。

历史发布前后，活动增量不可立即删除。旧版本与未归档日志仍是恢复依据。

## 6. 操作与失效边界

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D12、D16、D17（含验证及回退）。

编辑、重新生成、压缩、分支、截断、导入及外部来源更新不一定符合追加语义。必须更新来源修订并使受影响派生视图失效，按既有显示语义重建；不能仅追加导致旧消息复现。

历史分页必须保留全局展示坐标、工具关联及场景扩展。msg_limit不一定等于返回行数，禁止为提速硬截断工具场景。

上一轮写入mutation闭合后，可在后台归档时开始下一轮；不是允许旧源重叠写。新轮使旧候选修订过期时拒绝其发布，并由后续任务覆盖尚未归档的连续事件，不丢弃旧任务的有效数据。

## 7. 故障与容量治理

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D01、D04、D08、D20、D21、D25（含验证及回退）。

- 归档失败：旧历史只作为有明确版本标签的历史快照可读，不冒充当前稳定结果；来源及权限校验不通过则退旧路径。未归档增量保持可恢复，活动读取须另满足v2资格。
- worker崩溃：持久化任务可重新领取；重复处理不重复插入消息。
- 重启：从持久化日志和任务恢复，不依赖进程内缓存。
- 队列积压：有界worker并发、内存预算、积压监控、重试退避与背压；不无限积压在RAM。
- 大历史整理：分批、有界资源，不将全库重建放进GET或服务启动关键路径。
- 来源不确定或校验失败：不发布候选；旧有效视图可读但明确版本状态。权限变更立即生效，不能继续暴露旧缓存。
- 不自动删除原始日志、数据库、旧版本、备份或staging；任何清理另获明确批准。

## 8. 技术选择

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D02、D03（含验证及回退）。

首选复用现有journal、进程内热缓冲、持久化整理任务以及SQLite展示表或分块文件。Redis不是前提，也不作为权威正文唯一存储。

编码详细设计选定独立SQLite派生库内的不可变行段及版本清单；不是额外分块文件服务。事务、跨进程写方资格与任务约束按protocol-v2规定，均待验证。若未来确有多进程共享缓存或吞吐需求，再单独评估Redis持久化、故障恢复及运维成本。

## 9. 实施顺序与门禁

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D22、D23、D26（含验证及回退）。

1. 编码设计：盘点全部读写调用方、身份及修订来源，确定schema/文件协议、预算、事务和回滚边界；审查通过再编码。
2. 建立历史展示结果与分页索引，先候选构建并与现有展示哈希比对。
3. 接入活动journal增量读取，证明历史水位与SSE游标一致。
4. 引入后台整理、幂等任务、原子发布及故障恢复。
5. 将统计、Todo、工具关联等派生维护迁到写入侧；上下文信息刷新退出同步GET。
6. 按会话逐步后台构建存量视图；尚未构建者明确走兼容旧路径，不能声称全量已优化。
7. 最后独立评估正文重复存储及旧路径退役，不提前停止sidecar兼容写入。

本地回归后沿既有 `.10` 路线受控验收，不另建测试部署；发布须有单独执行授权及活动运行检查。实现从已验收生产基线推进，不混入此前回滚候选。

## 10. 验收要求

风险与处理：见 [逐项风险矩阵](session-read-write-separation-risk-matrix.md) D22、D26（含验证及回退）。

- 正文、角色、顺序、展示总数、工具关联、分页和截断标记与既有批准语义一致。
- 覆盖普通完成、失败、取消、中断、重启、worker重复执行、任务登记失败、过期发布、并发下一轮及分页跨版本。
- 覆盖编辑、再生成、压缩、分支、外部更新、权限与profile隔离、显式空Todo。
- 已构建且来源未变的稳定历史GET不调用全历史merge或全量大小扫描；正文GET不等待模型元数据联网刷新。
- 分别记录小会话、长会话、活动轮次、积压状态、冷/热请求及浏览器首屏；不能以内部函数或HTTP200代替端到端验收。
- 建议沿用待验证性能目标：小会话热GET p95≤200ms，长会话尾页p95≤800ms，受控冷首屏尾页≤2秒；这些是目标，不是已达成结果。
- 读回部署commit/image、健康状态、恢复结果、内存/队列预算及基线内容哈希；不通过则保持旧路径或兼容回滚。
