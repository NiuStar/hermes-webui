## P1 阻断

### CD-01：接口与序列化契约缺失
位置：编码设计18行；方案87—89行。
PlatformEvidence/ResourcePolicy/CandidateId/Manifest/ApprovalRecord/PublishResult只有名称，无字段表、函数签名、返回错误、字段来源及版本兼容规则。规范JSON没有完整限定重复键、非有限数、未知字段及字符串合法性。
反例：两个实现对未知字段保留/丢弃不同，或同一批准记录在不同解析器下得到不同含义；无法确定摘要和批准绑定是否一致。
关闭条件：逐类型字段/类型/必填/边界/可信来源/不可变性；规范字节和解析拒绝规则；API参数、返回类型与异常映射；相同摘要与歧义输入拒绝测试规格。不得替换或归一化非法标识符。

### CD-02：持久状态机与恢复判定未定义
位置：编码设计19、21行；方案91—95、114行。
缺失状态枚举全表、外部注册表介质、原子写规则、转换权限、幂等键和并发比较条件。方案发布顺序不能替代精确恢复状态表。
反例：rename成功但完成记录未写；重启同时看到批准记录与目标目录，两个恢复进程均推进，或目标与源都存在但归属不明。当前没有规定返回、锁与权威记录。
关闭条件：每条转换的前置状态/角色/持久写/同步顺序/线性化点/失败状态；源有无×目标有无×批准有无×完成记录有无的决策表；冲突保留与读回规则。不能仅凭路径存在认定成功。

### CD-03：权限证据的有效期与锁所有权不闭合
位置：编码设计20行与31行；方案79—83行。
专用UID方向已描述，但接口没有规定谁持有目录句柄、谁可构造权限证据、从检查到SQLite关闭及发布期间谁持锁、锁顺序、何时失效、异常时如何释放。普通数据结构不能作为安全能力。
反例：预检时目录受控，消费PlatformEvidence前ACL或挂载改变；缓存证据仍被接受。前后stat不能阻止中间替换。
关闭条件：可信创建/消费入口、能力对象寿命、真实权限前提与失效规则、锁顺序和释放表；对不支持ACL/挂载证据的失败码；跨进程反例。实际权限配置仍属后续授权，不能要求本轮擅自创建UID。

### CD-04：旧初始化入口与新连接入口的调用边界缺失
位置：编码设计13—14行；方案73、103行。
旧initialize明确待处理，但没有调用者清单、迁移/禁用策略；新连接工厂依赖“可信已激活库”，而激活不在当前交付范围，没有定义接受何种不可伪造输入。
反例：新发布入口安全，但旧调用仍对未知库切换WAL；或普通调用方把path/布尔值包装成“已激活”绕过入口。
关闭条件：完整调用点及替换计划；旧接口拒绝或仅测试保留的具体机制；当前有限切片只到发布未激活，连接工厂要么明确延期，要么精确定义可信资格接口且当前不授权。保留原WAL反例及迁移后新入口负对照。

## P2 必须在编码设计放行前关闭

### CD-05：资源策略只有参数名，没有执行语义
位置：编码设计22行；方案112行。
缺少单位、包含范围、阈值关系、预算预留原子性、硬限额提供者、失败候选计数范围与审计写入预留。并发1的执行范围也未定义为线程/进程/主机。
关闭条件：明确量纲、计数对象、比较边界、预留/释放责任、无硬限制能力时拒绝的返回规则及并发上限机制。实际数值可作为实施前必须输入的测量策略，不必为文档放行编造生产阈值；但接口和缺失处理必须完整。

### CD-06：验收矩阵仍是待办，不能验证契约
位置：编码设计23、30—35、39行。
无精确测试目标、夹具前置条件、注入点、预期错误及磁盘/事务/权限后置状态。风险表不是验收规格。
关闭条件：按CD-01至05和WAL/immutable/no-replace/fsync/已有目标/崩溃重入建立逐测试矩阵，列创建对象、故障点、返回值、持久状态、原库不变项及证据；明确预期失败与环境阻断；进程崩溃不冒充断电验证。
