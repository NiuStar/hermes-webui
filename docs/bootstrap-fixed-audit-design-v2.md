# 固定审计日志方案 V2

状态：REVISED_PENDING_REVIEW；仅方案修订，不授权功能编码、SQL、部署。替代V1方案，V1保留不改。
V1来源：/workspace/.hermes/plans/2026-09-08_184253-bootstrap-fixed-audit-design.md；SHA256 e0281d930a230ab0dd8cb54f72b23d2896113b7fbe208514310cce3a62dd9025。

## 1. 目标与边界

每候选一个预创建、完整写实且同步的固定长度审计文件。状态、平台证据、失败证据存储在固定槽，不再在候选构建之后创建、移动或删除审计目录项。仅离线创建、外部批准、发布未激活和恢复；禁止运行库接线。

保证属于“获批存储条件、可信实现、专用UID下避免审计追加分配空间”，不是防恶意同UID写入或任意硬件损坏保证。SHA提供损坏检测，不提供抗篡改身份认证。root和部署管理员可信；其变更必须遵守同一全局锁和运行隔离。

## 2. R1：保守恢复，不跳过歧义槽

V2撤销V1“重启跳过未提交槽继续追加”的规则，选择可用性较低但无需猜测的规则：
- 初始化头部提交并同步之前，全部槽为已实际写零、已同步；头部不完整则整容器不可写。
- 合法容器是连续有效已提交物理槽前缀，后接全零尾部；逻辑registry序号另按连续链核验。证据也占物理槽。
- 任何非零但未完整提交槽、控制区损坏、摘要错误、全零间隙后出现非零槽，全部返回AUDIT_UNAVAILABLE/只读保留；不跳过、不覆盖、不追加、不自动隔离写入。
- 已提交槽的业务语义错误、重复逻辑键、跨候选或链错误同样阻断。不得回退到历史成功终态。
- 写领取区→fsync读回→payload→fsync读回→提交区→fsync整槽读回。任一步失败，当次停止，不重试换槽。
- 提交后fsync报错但恢复看到完整有效记录时，先对文件再次fsync和读回，确认成功才能使用该记录继续恢复；否则只读阻断。
- 任意损坏把整个末尾提交槽变成全零，与未使用槽无法仅靠单文件区分。该情况不在“同步正确、未发生已持久数据丢失”的崩溃模型内；发现存储回滚、介质错误或外部摘要不一致即阻断。V2不声称能检测任意全零回滚；如要求该保证，需另设计独立持久高水位见证，不能靠双份同盘标志冒充独立证据。

风险：一次未完成追加会使容器不可继续使用。对策：保留文件、禁止复用ID，由人工诊断，不自动重建。验证：逐次pwrite/fsync中断，末尾完成/隔离记录提交区损坏，逻辑链损坏，保证不复活、不跳槽。

## 3. R2：写入范围执行与FD边界

- 固定长度由可信审计模块执行：全部offset/length在写前验证，禁止整数溢出；每次写后和fsync读回后核对文件身份、长度、链接数及分配状态。
- Landlock只限制路径/文件权限，不限制pwrite偏移；明确不宣称内核强制固定字节长度或不可修改历史。
- 模块不导出裸可写FD，禁止truncate/fallocate/追加模式；审计文件初始化后不得变长。越界请求在系统调用前拒绝，写后长度变更立即停止并保留证据。
- 准备阶段拥有可写FD；所有准备写入完成后关闭可写FD，保留只读或O_PATH身份句柄。通过全进程FD扫描后安装Landlock，仅当前审计文件允许WRITE_FILE，不允许TRUNCATE；目录无MAKE/REMOVE/REFER权限。安装后重新打开同一文件为O_RDWR并核对held/named身份。
- creator另获当前候选目录写权限；publisher仅有候选/发布目录移动权和当前审计文件写权。不增加新日志目录。

风险：可信实现缺陷仍可能越界扩展或改写历史。对策：集中所有写调用、封装检查、回归与独立代码审查。验证：偏移负数/越界/边界值、已有可写FD、替换文件、扩展尝试；如果产品要求抵抗恶意工作进程，本路线不满足，必须另行设计受信写入代理。

## 4. R3：空间门禁分阶段

|阶段|空间规则|允许行为|
|---|---|---|
|新候选准入/审计准备|检查实际空闲块、inode、保留数；物理预算覆盖头部、控制区、填充和所有槽|准备失败不得创建候选数据库|
|准备完成后的正常推进|候选卷遵守候选配额和批准余量；审计检查已分配完整性、可用槽，不再重复要求同额空闲audit_reserve_bytes|资源不符停止新增业务推进|
|失败审计|只使用已准备容器的合法全零尾部，检查身份、完整前缀和失败槽余量|不因审计卷空闲块/inode为零而拒绝预分配覆盖|
|恢复收尾|完整验证原意图、目标、外部批准及容器；仅对现有合法槽覆盖，不扩容|可补完成；不隐式执行新创建|
|完成结果只读确认|完整读回现有证据，不要求还有空槽或新增审计空间|返回已完成结果，不追加成功记录|

满盘不授权继续不安全的候选写入或缺空间的目录移动。失败收尾仍受同一进程硬时限约束；被SIGKILL后由新的获批恢复进程处理，不能延长原时限。日志已损坏时禁止为记录失败而覆盖损坏槽。
验证：分别耗尽审计数据块、inode、候选配额；同时覆盖实际生命周期收尾而非仅低层pwrite。保留故障卷，清理另授权。

## 5. R4：首版存储准入范围

首版拟支持：独立ext4审计卷位于完整分配且实际写实的loop文件；backing位于直接、非CoW的ext4宿主文件系统。首版拒绝XFS、Btrfs、ZFS、网络文件系统、overlay、嵌套loop、device-mapper/thin/snapshot等尚未证明的层。此为支持范围收窄，必须随独立方案审查批准。

程序证据：通过held FD的mount_id和dev定位mountinfo/sysfs，验证loop的offset/size/backing身份；验证backing宿主挂载和设备拓扑，无符号链接/稀疏/未知中间层；验证文件extent完整写实（编码设计须指定查询及拒绝标志），journal能力和读写挂载特征。所有证据绑定配置SHA和真实身份，每次运行复读。

无法从guest证明hypervisor、阵列和物理介质绝不CoW或正确执行flush。受保护的管理员存储契约必须列明这段不可观察边界、固定部署身份及“不超售、无快照回滚、正确flush”责任；不是把管理员字符串当作可观测事实。能力证据分为程序实测、管理员保证和故障验收三栏，任何必需项缺失均不签发。当前.10是否支持该拓扑尚未调查，不能承诺可用。

验证：审计卷和backing宿主空间分别耗尽的负对照；同步/断电结果分别记录；有限测试只证明该固定组合，不能外推所有ext4。拓扑变化、存储契约撤回或错误出现时关闭准入，保留文件。

## 6. R5：上下文与操作准备分层

签发前：固定全局锁、active/anchor、部署与资源SHA、角色及根身份、systemd/cgroup、seccomp、存储证据、DDL/平台、介质版本全部核验；准入开始时间作为协作期限起点。最后复读关键证据，成功才单次转移FD/锁所有权；任何失败关闭所有自有FD。

Context表示获准进行受控准备，不表示当前候选的审计已准备。creator必须先准备固定容器并提交RESERVED，再建候选目录/配额，关闭所有可写普通文件FD，安装限制，再重新打开审计文件。publisher/recover先只读检查容器及候选状态，再安装对应限制，按操作需要重新打开审计文件。

|通道|限制前|限制后|
|---|---|---|
|角色核验|DAC有效访问、祖先身份、ACL和UID|不以已故意移除的目录写权限判断失败；复核持有/命名身份、owner/mode/ACL、UID及明确的Landlock角色策略|
|硬限制核验|systemd/cgroup及seccomp实际检查|同样复核，不信任缓存结果；systemctl/busctl子进程仅获继承的只读/限定写能力|
|配额代理|无持久socket，申请/核验完成后关闭|每次新建AF_UNIX连接，验证peer和回包，关闭后再进行FD检查|
|审计|准备时可create/分配|仅重新打开指定inode覆盖，禁止目录写|
|退出|关闭局部句柄/锁|不解除不可逆限制；一次操作后退出|

代码必须把DAC配置证明与Landlock后的有效写权限检查分开，不能简单跳过revalidate。真实受限进程若不能连接system bus/quota socket或执行只读检查，判环境BLOCKED，禁止把内存快照替代实时核验。前台.10隔离能力验证是进入正式可用状态的必要条件。

## 7. R6：逻辑记录预算和外部审批

每个registry记录、平台证据、失败证据各占一个固定槽。物理预算包含固定头部、全部控制区、payload填充及文件系统分配取整；精确字节常量留编码设计，但资源必须使用新格式版本与物理预算，旧65536倍数规则不能沿用。

最低初始业务需求：正常链RESERVED、BUILDING、VERIFIED、APPROVED、PUBLISH_INTENT、PUBLISHED_UNACTIVATED，平台证据一条，后续失败证据及失败/隔离状态两条。初始至少覆盖上述用途；不承诺无限恢复重试。

|当前状态/操作|最低新增槽需求|不足时|
|---|---|---|
|VERIFIED→发布|APPROVED、INTENT、完成，加失败证据/隔离余量|不写APPROVED|
|APPROVED→发布|INTENT、完成，加失败证据/隔离余量|不写INTENT|
|INTENT→完成|完成，加失败证据/隔离余量|保持INTENT，源/目标照旧|
|合法前缀后的失败/隔离|证据与状态所需槽|报告未持久化，不伪造终态|
|已完成的只读确认|零槽|不得因无空槽改成失败|

外部批准文件仍由独立approver创建并同步，拥有独立审批物理预算与根，不消耗creator容器槽。审批空间不足则没有可接受批准，publisher不得移动；不得由creator生成替代批准。资源配置需将creator审计预算与approver预算分开，部署绑定审批根及审批策略摘要。审批预算的管理配置、no-replace写入及读回属于同一新编码设计的必要项，不在本阶段实施。

## 8. 不变约束与迁移

旧介质/旧格式候选只读诊断，禁止原地转换、新旧混写或复用旧ID。logical JSON摘要与物理提交摘要分离；完整候选manifest绑定新介质/资源版本。预分配头部失败的孤儿仍计入保留数与物理占用。

新代码仅修改bootstrap相关模块，不改routes/server、运行库连接工厂或已有数据库。功能编码需要方案独立终审→编码设计独立终审通过。全面测试仅.10隔离，所有文件和失败库保留，清理另授权。独立评审禁止后台分派；作者复核不能当独立通过。

## 9. 本轮整改与验收清单

R1—歧义槽整容器阻断，接受可用性损失；验证末尾终态损坏不会回退。
R2—明确可信实现保证而非内核字节限制；验证偏移、FD、身份和限制后重开。
R3—区分准入/正常推进/失败收尾/只读确认；验证满盘时真实失败审计。
R4—限定存储拓扑，分离实测与管理员责任；验证未知层拒绝与双层空间耗尽。
R5—DAC与Landlock策略分层，规定FD顺序；验证三个真实独立进程的全部通道。
R6—按状态定义槽用途，独立审批预算；验证槽耗尽、审批耗尽及零槽只读确认。

以上为方案整改，不是实现或平台验收通过。精确布局、API签名、错误码表、故障矩阵、预算公式和管理配置schema必须在下一阶段给出。
