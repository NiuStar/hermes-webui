## V3-01 / P2：固定目录身份与正常目录变化缺少区分

位置：24、67、73—77、95—100行。
FileIdentity含nlink，DeploymentPolicy将该类型用于候选/注册/发布根和所有祖先，并要求重新检查身份。未定义目录哪些字段精确比较、哪些只是观测值。创建子目录会正常改变父目录链接数；若完整比较FileIdentity，会在创建或发布后拒绝自己的合法操作。若为绕过此失败重写策略，则D变化又使原审批失效。

整改：区分常规主文件身份与目录身份；目录稳定身份用dev/ino及受控uid/gid/mode等明确字段，nlink只记录为观测或定义允许变化，不作为根路径不可变性依据。主库nlink=1要求继续保留。策略不能因正常子目录增减自动改写；前后检查允许变化必须显式列出。

验证：真实目标文件系统上依次创建候选/注册目录、发布目录并重新获取ctx；策略摘要不变且合法操作不误拒；替换根inode、权限弱化、主库硬链接仍拒绝。当前仅提出测试规格，未实测。

风险/回退：正常流程自锁或实现者放宽全部身份校验；修订比较规则前不进入实现。

## V3-02 / P2：创建时平台证据只有摘要，没有持久读取来源

位置：25、27、81—83、91—98行。
发布需要从创建时PlatformEvidence取得D，并匹配Manifest.platform_evidence_sha=E。但有限发布目录只有主库与manifest，注册记录schema也不含平台证据全文；文档未指定该证据保存位置、写入同步阶段及重启读取路径。新ctx不能凭摘要恢复创建时证据内容，重新生成带新evidence_id的证据也不能得到同一个E。

整改：指定受保护外部证据库或注册目录中的不可变证据文件，明确命名、严格schema、O_EXCL/同步/读回顺序；VERIFIED前必须证据持久。发布按manifest的E读取并验hash及创建时D，不能以当前新证据代替；定义缺失/损坏返回与禁止重建历史证据。把占用计入审计预算且不违反候选精确文件白名单。

验证：创建进程退出后新进程只从持久制品完成绑定；证据丢失、损坏、替换、写入同步失败均零rename，保留候选。

风险/回退：正常重启无法验证，或实现者凭当前配置合成历史证明；缺证据即BLOCKED。

## V3-03 / P2：首次审批注册绑定与重入绑定未区分

位置：29、42—43、83、98—99行。
83行把approval_id与注册绑定相等列为发布必需条件；首次调用时最新状态VERIFIED，注册approval_id按定义尚为null，而98行要在VERIFIED→APPROVED时才写入。若所有条件在状态转换前统一执行，首次合法批准永远不成立；若直接忽略注册绑定，又可能放宽APPROVED及之后的重入检查。

整改：按状态定义匹配顺序。VERIFIED时要求approval_id为空，先验证受保护批准文件及其他等式，再追加APPROVED并持久读回绑定；APPROVED/PUBLISH_INTENT/PUBLISHED_UNACTIVATED时必须已有非空相同approval_id，拒绝换审批。说明recover_candidate无显式approval_id时只从最新有效注册链取值，VERIFIED无绑定时返回待批准拒绝，不猜文件或自动挑选批准。

验证：首次合法批准成功；相同批准重入幂等；不同批准即使候选/摘要相同也拒绝；APPROVED追加失败无rename；未绑定恢复不自动批准。

风险/回退：首次流程被永久阻断或重入错误更换批准；明确首次赋值与后续不可变比较，失败关闭。
